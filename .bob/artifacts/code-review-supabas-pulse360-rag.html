9
Section regex produces false positives on all-caps content
chunker.py:6

Correctness SECTION_RE second alternative matches any 4+ uppercase line — FAQ list items, table headers, acronyms (N/A:, URL:) all match, causing incorrect section splits that break chunk context and hurt retrieval quality.

Recommended fix

Require the non-markdown alternative to end with : (making it an explicit label). Alternatively restrict section detection to markdown headers only (#{1,3}\s+).

10
Sliding window can advance by 1 character on large overlap values
chunker.py:86

Performance start = max(start + 1, end - overlap_chars) — if overlap_chars approaches max_chars, the window advances by 1 character per iteration, producing millions of near-duplicate chunks and effectively hanging ingestion.

Recommended fix
start = max(end - overlap_chars, start + max(1, overlap_chars // 2))
11
Chroma cosine distance → similarity conversion is wrong
vector_store.py (deleted — note for future)

Correctness File deleted. If Chroma is re-introduced, this bug must not be carried forward: Chroma returns cosine distance in [0, 2]; 1.0 - distance can produce negative scores.

Correct conversion
score = max(0.0, 1.0 - distance / 2.0)

BEGIN IMMEDIATE scope not commented in preview()

13
No rate limiting on /search and /ask endpoints
api/routes.py:88

Security / Ops Both endpoints accept unlimited requests. A single client can saturate the HuggingFace embedding quota or LLM token budget. No per-IP throttle or circuit breaker is in place.

Recommended fix

Add slowapi middleware for per-IP rate limiting. Propagate request_id as X-Request-Id response header for cross-service log correlation.

14
New SupabaseLibrary instantiated on every search request
retriever.py:17

Performance SupabaseLibrary(settings).search(…) constructs a new object on every call, re-importing psycopg and resolving the connection string each time. Unnecessary per-request overhead in a warm instance.

Recommended fix

Inject a shared SupabaseLibrary via FastAPI's Depends(), matching the pattern already used in api/documents.py via get_library().

N1
Duplicate check misses live sha256 column
supabase_store.py:367

Correctness commit() checks checksum then content_hash for deduplication, but the live schema uses sha256. Re-uploading the same file to the live schema is never detected as a duplicate — an unnecessary embedding API call is made every time.

Recommended fix

Add a branch for sha256 first (highest priority), before the checksum and content_hash fallbacks.

N2
Raw match dicts (internal IDs, scores) sent directly to LLM as user content
llm/client.py:113

Security / Token cost synthesize() serialises the full match dict — including vector_score, document_id, page and filename — as the LLM user message. This inflates token usage, exposes internal IDs to the model, and contradicts the system prompt's "untrusted data" framing.

Recommended fix

Strip matches to only {"chunk_id", "text", "title", "section"} before passing to the prompt.

N3
Settings hard-crashes on startup for any non-HuggingFace provider
config.py:35

Flexibility __post_init__ raises ValueError if llm_provider != "huggingface", making the process unrunnable with any other provider. synthesize() already re-checks this at call time.

Recommended fix

Downgrade to a logger.warning in __post_init__; keep the hard check only in synthesize().

15
source_id derived from filename collides across directories
ingestion/loader.py:29

Collision Risk load_document() sets source_id = path.stem.lower().replace(" ", "-"). Two files named About Us.md in different subdirectories both produce source_id = "about-us". load_documents() uses a path-hash correctly, but direct callers of load_document() receive a colliding ID.

Recommended fix

Derive source_id from a SHA-256 of the full path in load_document() too, or at minimum document that callers must supply a unique ID.

16

schemas.py:31

Style RetrievedChunk exposes both score and a vector_score property returning the same value. API responses serialise both fields. Callers don't know which to use.

Recommended fix

Keep vector_score as the canonical public field. Remove score from the serialised response or mark it deprecated.

N4

chunker.py:48

Style Documents with no headings produce chunks where section = "FAQ", which appears literally in LLM citations as if the document has a section called "FAQ".

Recommended fix

Use an empty string "" or None as the default section name and handle it downstream in citation formatting.
